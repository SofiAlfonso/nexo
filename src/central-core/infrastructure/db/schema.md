# D2 — PostgreSQL 16

`createD2Pool(env?)` requires `D2_DATABASE_URL`; `D2_POOL_MAX` is an optional positive integer (default 10). The caller owns `pool.end()`. Call `await migrate(pool)` before serving C4. The runner loads numbered `.sql` files relative to its module, holds a D2 advisory session lock, and applies each migration and its `public.d2_schema_migrations` entry atomically. It verifies SHA-256 on subsequent runs. Keep the SQL files beside the module in deployed builds; never edit an applied migration.

`001_initial.sql` creates `m1_config_permisos` (client, venue, event, zones, points, readers, versioned tickets/permission changes and policies), `m2_evidencia` (idempotent batches and evidence, decisions, latest point/coordinator state, per-minute counts, incidents/actions, immutable audit log), `m3_conciliacion` (close and differences/resolutions), `m4_liquidacion` (contract and settlement), and `auth` (operators and sessions). Times are `timestamptz`, amounts are `numeric`, and foreign keys are scoped by event where applicable. D2 only observes decisions made by C2; it cannot authorize admissions. Do not store ticket buyers or plaintext passwords. Seed operator passwords must be hashed with argon2 outside SQL; no default credentials are provided. `auth.sesiones.id` should be an opaque random token identifier (prefer storing a digest, not the cookie token).

Deduplicate batches on `m2_evidencia.lotes.id_lote` and records on `m2_evidencia.evidencias(evento_id, tipo, id_origen)`; compare `contenido_hash` before treating a collision as a retry. Commit a batch, its evidence, derived state, and stored `acuse` together. `m2_evidencia.bitacora` rejects both updates and deletes; write new rows for corrections. Retain business evidence for at least 90 days; no automatic deletion is configured. No RLS is installed in this laboratory PoC (ADR-009); application code must scope reads and writes to the authenticated event/client.
